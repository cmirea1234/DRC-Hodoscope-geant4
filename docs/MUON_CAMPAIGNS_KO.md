# original 뮤온 통계 확대

기준 배치의 original로 서로 다른 seed를 사용한 500트리거 × 10개의 잡을 실행해 총5,000트리거를 수집했습니다. 모두 정상 종료하고 결과 검증을 통과했습니다. [결과 요약](../reference/knu_muons_5000_summary.json).

## 새 환경에서 확대하는 순서

1. [첫 실행 안내](INSTALL_KO.md)에 따라 5트리거 기준 집계까지 통과합니다.
2. 통과한 실행 파일과 Geant4 환경을 고정합니다. 실행 파일 해시와 입력 매크로, Python/라이브러리 버전을 기록합니다.
3. 500트리거 한 잡을 실행합니다. `scripts/run.py original --target 500 --seed 새정수 --build-dir 검증빌드경로 --output 새출력경로`를 계산 노드에서 수행하고 `scripts/validate_root.py 출력경로`를 실행합니다.
4. 검증되면 서로 겹치지 않는 seed와 출력 폴더로 잡을 나눕니다. 시작 시도마다 새 디렉터리를 만들어 실패/재시도 결과가 덮어써지지 않게 합니다.
5. 각 잡의 정상 종료와 `VALIDATION.json`의 PASS를 확인한 결과만 합산합니다.

잡당 한 Geant4 프로세스/1 CPU를 사용했습니다. 500트리거는 생성 입자 500개가 아닙니다. 이번5,000트리거 시험에서는 뮤온1,103,858개를 생성했습니다. 잡10개는 서로 다른 물리 노드10개를 보장하지 않습니다.

이 저장소의 기존 `knu_*` 운영 스크립트에는 당시의 서버 경로·바이너리 해시·실행 이력이 들어 있습니다. 새 환경에서 자동으로 적용되는 범용 캠페인 실행기로 취급하지 않습니다. 새로 받은 환경은 첫 실행으로 검증한 자신의 빌드·공유 경로와 사이트 정책을 사용해야 합니다.

## 합산 원칙

- 사건 식별자는 `(seed,event)`입니다. 다른 잡에서 같은 event 번호가 나와도 같은 사건이 아닙니다.
- seed를 바꾸지 않은 재실행은 독립 통계가 아닙니다. 재시도로 성공 결과가 둘 생겨도 한 번만 사용합니다.
- 응답률은 성공한 모든 잡의 신호 count 합계 / T1&T2 트리거 합계로 계산합니다. 잡별 비율을 무조건 단순 평균하지 않습니다.
- 네 평면 조건부 응답은 1,759/5,000=35.18%, Wilson 95% 구간33.87~36.51%였습니다. 검출기 고유 효율이 아닙니다.
- 여러 잡의 CPU/실행 시간 합계와 전체 캠페인의 벽시계 완료 시간은 다릅니다. 병렬 실행의 효과는 별도로 기록합니다.

## 상태 확인

```bash
condor_q 실제잡번호 -nobatch
condor_q 실제잡번호 -af ProcId JobStatus RemoteHost HoldReason
condor_history 실제잡번호 -af ProcId JobStatus ExitCode
```

큐에서 사라졌다는 것만으로 성공을 판단하지 않습니다. 실행 로그, 종료 코드, ROOT 검증 결과를 함께 확인합니다. 통과하지 않은 잡이 있으면 일부 결과임을 명시하고, 원인을 확인하기 전에 전체 캠페인을 같은 seed로 재제출하지 않습니다.
